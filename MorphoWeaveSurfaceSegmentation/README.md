# MorphoWeave Surface Segmentation

Surface Segmentation assigns one population-consistent region label to every dense correspondence locus using [`hdmseg`](https://github.com/agporto/hdmseg), then propagates those labels to each paired full-resolution mesh.

## Method

The module stacks the paired correspondence files into an array of shape `(specimens, loci, 3)`. `hdmseg` builds a fixed neighborhood graph on a reference correspondence set, evaluates locally scaled affinities within every specimen, averages them into a consensus diffusion operator, and clusters the leading spectral modes. The resulting locus partition is shared across all specimens.

This replaces the former MorphoWeave implementation based on hand-engineered curvature, dihedral, normal-variation, orientation, and optional HKS features. Surface geometry still affects the result through the population correspondence coordinates, but no feature-versus-spatial mixing parameter is used.

## Inputs

- **Meshes folder**: full-resolution meshes to receive labels.
- **Dense correspondences folder**: matching `.mrk.json` files generated by Atlas Builder.
- **Reference correspondences**: optional. If blank, the module first looks for the canonical Atlas Builder file `atlas/atlas_dense_correspondences.mrk.json`; if it is not available, the specimen-wise mean correspondence shape is used.
- **Output folder**: parent directory for isolated per-run exports, described below.

Mesh and correspondence filenames must have the same base name. Every correspondence file must contain the same number and order of loci.

## Region selection

- **Fixed number of regions** uses the requested `k` directly.
- **Bootstrap stability** selects `k` by specimen resampling and is most informative with roughly 15 or more specimens.
- **Modularity** chooses the partition with the highest graph modularity without bootstrap solves.
- **Eigengap** chooses `k` from the leading normalized-operator spectrum.

`hdmseg>=0.2,<0.3` uses an edge-sparse consensus operator and a partial eigensolver for large connected graphs, with a validated dense fallback for small, disconnected, or non-converged cases.

## Mesh propagation

Locus labels are transferred to full-resolution vertices by nearest-locus assignment in each specimen's own coordinate frame. Optional mesh-adjacency majority smoothing is then applied. The Slicer preview and labeled VTP use point labels; separate PLY regions assign every triangle to the majority label of its vertices.

## Outputs

Each run creates a new, exclusively allocated subdirectory inside the selected
output folder, named `MorphoWeaveSurfaceSegmentation_<date>_<time>_<unique suffix>`.
All files below belong to that run directory, which is shown in the completion
message and returned as `result['output_directory']` by the logic API:

- `MorphoWeaveSurfaceSegmentation_locus_labels.npy`
- `MorphoWeaveSurfaceSegmentation_locus_labels.csv`
- `MorphoWeaveSurfaceSegmentation_embedding.npy`
- `MorphoWeaveSurfaceSegmentation_eigenvalues.csv`
- `MorphoWeaveSurfaceSegmentation_summary.json`
- optional `<specimen>_segmented.vtp` files containing `SegID` and `SegID_smooth`
- optional `<specimen>_seg_<ID>.ply` region meshes

The summary records the `hdmseg` version, reference file, parameters, modularity, stability, timing, generated files, warnings, and any mesh-export failures.

Rerunning with fewer regions never leaves stale region files in the new result.
Earlier runs, legacy exports in the parent directory, and unrelated files are
not overwritten or deleted. Consumers should use one run directory and its
summary, not recursively pool region files across runs. An export error remains
recorded in that run's summary as before; isolation is not a claim that every
specimen exported successfully.

The Run button, backend installer, and inputs are disabled during execution,
including dependency installation. Validation and selection callbacks cannot
reenable Run while busy. Controls are restored on success, declined installation,
and exceptions, with mode-specific settings revalidated.

## Validation

Ordinary Python tests (NumPy, SciPy and VTK required):

```bash
python MorphoWeaveSurfaceSegmentation/Testing/Python/SurfaceSegmentationSourceTest.py
python MorphoWeaveSurfaceSegmentation/Testing/Python/SurfaceSegmentationWorkflowTest.py
```

The workflow tests exercise real VTP/PLY writers and projection with a
predictable test segmentation backend; Qt/Slicer are doubled. They verify
rerun isolation, preservation of old files, output options, reported failures,
run reentry, installation reentry, and control restoration. They are not a
native hdmseg or live Slicer validation.

After installing this branch and `hdmseg>=0.2,<0.3`, run the native smoke test in
a **fresh Slicer process** with this extension available:

```bash
Slicer --no-main-window --python-script MorphoWeaveSurfaceSegmentation/Testing/Python/SurfaceSegmentationSlicerSmokeTest.py
```

It uses real MRML loading and native hdmseg on synthetic meshes, reruns with
three then two regions, verifies nonempty PLY exports and unchanged old files,
and prints `SURFACE_SEGMENTATION_SMOKE_PASSED` before exiting with status 0.
Failure exits with status 1. It does not install dependencies. This live test
must actually pass in the target installation before merge signoff.
